# 분석 흐름 (노드 기반 종목 분석)

노드를 이어 붙여 `종목 가져오기 → 차트로 거르기 → AI 분석 → 결과 확인` 흐름을 만들고 실행한다 (`/flows`).
갈래를 나눠 따로 거른 뒤 합치기 노드로 교집합·합집합을 낼 수 있다.

지금은 **기능 검증 단계**라 시세를 yfinance에서 받는다. 어떤 지표·기간·데이터(수급·재무)가 실제로 필요한지
써 보고 정한 뒤 수집 DAG(백필 포함)를 만든다 — 7절.

## 1. 노드

노드 사이로는 `StockSet`(종목 → 행)이 흐른다. 행에는 코드·이름과 앞 노드들이 계산한 값이 쌓이고,
`fields`가 열 이름·서식을 들고 다녀서 결과 표가 열을 따로 정하지 않는다.

| 노드 | 입력 | 하는 일 |
|------|------|---------|
| 종목 가져오기 `source` | 0 | ETF가 담은 전체 종목(559) / 특정 ETF 구성종목 / 내 포트폴리오 실보유(ETF는 구성종목으로 풀고 직접 보유 주식은 그대로) / 직접 입력 |
| 차트로 거르기 `chart_filter` | 1 | 켠 조건을 모두 만족하는 종목만 남긴다: 이평 정배열(5>20>60), 종가 > N일 이평, N일 고가 대비 −x% 이내, 20일 수익률 범위(기간 고정), 거래량 배수, RSI(14) 범위, 간이 VCP. 일봉이 60일보다 짧으면 제외 |
| 합치기 `combine` | 2+ | 교집합(첫 입력 순서 유지) / 합집합. 같은 종목의 값은 앞 입력 값이 남는다 |
| AI 분석 `ai_analysis` | 1 | 앞에서부터 최대 N종목(기본 10)을 LLM으로 3문장 근거 정리. 관점: 종합 / 추세 / 위험 |
| 결과 확인 `result` | 1 | 정렬 기준·최대 종목 수로 표를 만든다 |

- 노드 1종 = 파일 1개 (`backend/app/services/flow/nodes/`), `REGISTRY`에 올리면 팔레트와 설정 폼이 따라 생긴다.
- 설정 폼은 노드의 pydantic `Params`에서 만든 명세(`param_spec`)로 그린다. 선택지 이름은 `json_schema_extra={"options": ...}`,
  다른 값에 따라 보이는 항목은 `show_if`, 포트폴리오·열 고르기 같은 특수 입력은 `widget`.

### 간이 VCP

미너비니 VCP의 핵심만 옮긴 근사다 (`indicators.is_vcp`): 최근 60거래일을 20일씩 세 구간으로 나눠
① 변동폭((최고가−최저가)/최고가)이 차례로 줄고 ② 마지막 구간이 10% 이하이고 ③ 종가가 60일 고가에서 10% 안이며
④ 마지막 구간 거래량 합이 첫 구간보다 적다.

### AI 분석

- 숫자는 백엔드가 계산하고 LLM은 문장만 쓴다 (챗봇과 같은 원칙). 넘기는 사실: 앞 노드가 계산한 값,
  일봉으로 계산한 5·20·60일 수익률·기간 고가 대비·RSI·거래량 배수·정배열·VCP 여부, 담은 ETF 수와 비중 상위 3개.
  앞 노드가 이미 낸 값은 다시 넣지 않는다.
- 매수·매도 권유, 예측, ETF 편입의 의미 추측은 금지. 한자가 섞이면(qwen이 가끔 섞는다) 한 번 다시 쓰게 한다.
- 동시 요청 3개. 클라이언트가 끊으면 남은 요청은 보내지 않는다.

## 2. 실행

`POST /api/flows/run {graph}` — 저장하지 않은 그래프도 바로 실행하고 SSE로 노드별 진행을 보낸다.

- 그래프 모양 오류(모르는 노드, 없는 노드로 가는 연결, 순환, id 중복)는 스트림을 열기 전에 400.
- 위상 순서로 한 노드씩 실행한다. 입력 수·설정 오류나 실행 실패는 그 노드의 `node_error`로 알리고,
  **그 뒤로 이어진 노드만** `node_skipped`, 다른 갈래는 계속 돈다.
- 이벤트: `run_start` · `node_start` · `node_progress` · `node_done {count, badge, dataset, notes, seconds}` · `node_error` · `node_skipped` · `run_done`.
  `dataset`은 챗봇 답변의 `Dataset`과 같은 형식이라 화면은 `components/answer/DataTable`을 그대로 쓴다 (노드당 최대 300행).

## 3. 시세 (`market_data.py`)

- `MarketData.bars(codes)` 하나만 노드가 부른다. 지금 구현은 `YFinanceMarketData` — 1년 일봉(수정주가).
- 코스피(`.KS`) → 코스닥(`.KQ`) 순서로 시도하고 종목별 시장을 기억한다 (559종목: 코스피 408, 코스닥 151).
- 프로세스 메모리에 6시간 캐시. 첫 실행은 559종목 일괄 다운로드에 약 30초, 이후 실행은 즉시.
- yfinance는 비공식 API라 막히거나 형식이 바뀔 수 있다. 운영 데이터 공급원으로 쓰지 않는다.

## 4. 저장

`analysis_flows(id, user_id, name, graph JSONB, created_at, updated_at)` (마이그레이션 0022). 개인 저장만 하고 실행 결과는 저장하지 않는다.
`GET/POST /api/flows`, `GET/PUT/DELETE /api/flows/{id}`, 노드 목록·추천 조합은 `GET /api/flows/catalog`.

## 5. 화면 (`frontend/src/app/FlowPage.tsx`)

- 왼쪽 팔레트(추천 조합 + 단계별 노드, 누르거나 끌어 놓기), 가운데 캔버스(`@xyflow/react`), 노드를 고르면 오른쪽에 설정·결과 패널.
- 연결은 순환·중복·입력 수 초과를 막는다. 연결 끝을 끌어 다른 노드로 옮기고, 빈 곳에 놓으면 지운다. Delete/Backspace로 고른 노드·연결을 지운다.
- 실행 뒤 노드마다 `✓ 26종목` 같은 배지, 결과 탭에는 노트·AI 카드·표.
- 모바일은 팔레트를 대화상자로, 패널을 캔버스 아래로 둔다.

## 6. 추천 조합 (`templates.py`)

| 이름 | 흐름 |
|------|------|
| 기본 스크리닝 | 전체 → 정배열 + 120일 고가 −10% 이내 → AI(10) → 결과(수익률 순) |
| 이중 확인 교집합 | 전체 → [정배열] ∩ [20일 수익률 ≥ 0, 거래량 1.5배] → 결과 |
| 변동성 수축 | 전체 → 간이 VCP → AI(추세) → 결과 |
| 내 포트폴리오 과열 점검 | 내 포트폴리오 → RSI ≥ 70 → AI(위험) → 결과 |

## 7. 아직 하지 않은 것 / 다음에 정할 것

| 항목 | 상태 |
|------|------|
| 시세 수집 | yfinance로 검증 중. 필요한 기간이 정해지면 KIS 일봉 백필(559종목 × 1년 ≈ 1,700회 호출, 2~3분) + 신규 편입 종목 과거치 수집으로 바꾸고 `MarketData` 구현만 교체 |
| 수급(외국인·기관) | 수집 안 함. yfinance에도 없다. 필요하면 KIS 투자자 API를 매일 쌓아야 한다(과거치 약 30일만) |
| 재무(PER·ROE) | 수집 안 함. yfinance `.info`는 빈 값이 많다 |
| ETF 신호 노드 | 담은 ETF 수·액티브 ETF 신규 편입/비중 증가로 거르기 — 다음 단계 |
| 백테스트·리스크 노드 | 데이터 확정 후 |

**종목 범위**: ETF가 상위 30위 안에 담은 주식(559개)만 대상이다. 시장 전체 스크리너가 아니다.
