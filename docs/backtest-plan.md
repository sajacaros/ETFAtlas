# 스크리너 백테스트 계획 (검토 단계)

저장한 스크리너는 지금 **사후 채점**(기록한 날부터 앞으로 쌓아 가며 채점)만 된다 — [analysis-flow.md](analysis-flow.md) 4-1.
과거로 돌려 보려면 "그날 상장돼 있던 전 종목의 일봉"이 있어야 생존 편향 없이 돌릴 수 있다. 그 데이터를 KRX에서 받아 백테스트를 붙이는 계획이다.

## 1. 데이터 원천

| 원천 | 상장폐지 종목 | 기간 | 판단 |
|------|---------------|------|------|
| KRX 정보데이터시스템 (pykrx `get_market_ohlcv_by_ticker(날짜)`) | 그날 거래된 종목이 다 나온다 | 1995년부터라고 알려짐 (미확인) | **채택 후보** |
| KIS Open API | 지금 상장 종목만 | 한 번에 100일 | 불가 |
| yfinance | 없음 | — | 불가 |
| FnGuide 등 유료 | 있음, 수정주가 포함 | — | KRX가 안 되면 검토 |

- 2026-10-26 확인: KRX는 **로그인이 필요하다**. pykrx가 `KRX_ID`·`KRX_PW` 환경 변수를 요구하고, 없으면 모든 날짜가 빈 응답이다.
- 날짜당 1요청으로 그날 전 종목(시가·고가·저가·종가·거래량·거래대금·시가총액·상장주식수·전일 대비)을 받는다.

## 2. 규모

- 1995~2026 약 7,800거래일 × 평균 1,800종목 ≈ 1,400만 행, 인덱스 포함 2GB 안팎.
- AGE 그래프가 아니라 일반 테이블 `daily_bars(code, date, open, high, low, close, volume, value, market_cap, shares, adj_factor)` — 연도 파티션 검토.
- 수집은 날짜당 1요청이라 몇 시간 수준(추정). 이후 매일 증분.

## 3. 풀어야 할 문제

1. **수정주가** — KRX 시세는 원래 가격이라 액면분할·증자일에 가짜 급등락이 생긴다.
   방안: 기준가 = 종가 − 전일 대비. 기준가가 전날 종가와 다르면 권리 변동일로 보고 `기준가 ÷ 전날 종가`를 누적 보정 계수로 쓴다.
   **PoC의 핵심 검증 대상** — 맞지 않으면 여기서 접는다.
2. **노드별 가능 여부**
   - 차트 필터: 가능.
   - 대상 종목: "ETF가 담은 전체 종목"은 현재 목록이라 편향 → 백테스트용 시점별 유니버스(그날 시가총액 상위 N, 시장 전체 + 거래대금 하한).
   - ETF 신호: 구성종목 이력이 수집 시작 뒤부터만 있어 불가 → 백테스트에서 막는다.
   - AI 분석: 비용과 미래 지식 문제로 건너뛴다(통과만).
3. **상장폐지 처리** — 지금 `score_run`은 청산일 종가가 없으면 뺀다. 백테스트에서는 마지막 거래 가격(정리매매)으로 청산해야 편향이 안 생긴다.
4. **계산 속도** — `domain/indicators.py`는 종목 하나씩 순수 파이썬이라 10년 × 2,500종목 × 매일이면 수백만 번 호출. pandas/numpy 일괄 계산 버전을 따로 두고 기존 함수와 값이 같은지 테스트한다. 리밸런싱 주기(매일/매주) 선택.
5. **기간** — 1990년대는 코스닥 개장(1996), IMF, 가격제한폭(±15% → 2015년 ±30%)이 달라 성격이 다르다. 데이터는 다 모으되 기본 기간은 2010년 이후.
6. **기타** — 거래세·수수료 설정값으로 차감, 2002년 이전 기준 지수는 KOSPI200, KRX 이용약관(재배포 제한) 확인.

## 4. 구조

- 백테스트 = 과거 날짜마다 스크리너를 돌려 가짜 `flow_runs`를 만들고 기존 `performance.score_run`으로 채점 — 진입(다음 거래일 종가)·청산·지수 비교 규칙과 성과 화면을 그대로 쓴다.
- 노드 실행은 `MarketData`에 기준일을 주는 시점 고정 구현(`as_of` 이후 일봉을 안 보이게)으로 미래 참조를 구조적으로 막는다.

## 5. 단계

1. **준비** (사용자): KRX 회원 계정 → `.env`에 `KRX_ID`·`KRX_PW`.
2. **PoC (1~2일)**: 최근 2년 전 종목 수집 → 보정 계수 계산 → 분할 이력 종목(예: 2018년 삼성전자 50:1)을 KIS 수정주가와 대조. 1995년 날짜가 실제로 나오는지도 확인.
3. **판단**: 보정이 KIS와 맞으면 계속, 아니면 유료 데이터 검토 또는 중단.
4. **본 구현**: 전 기간 수집 DAG + 매일 증분 → 일괄 지표 계산 → 시점별 유니버스 노드 → 백테스트 API(기간·리밸런싱 주기·비용) → 성과 화면 재사용.
