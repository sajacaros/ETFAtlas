되묻기

"반도체 ETF 구성종목"처럼 대상이 여럿이면 하나를 골라 넣지 않고 etf_choice 슬롯이 후보를 보여 주며 묻습니다. 이름이 여러 ETF에 걸릴 때도 데이터 스킬이 같은 방식으로 되묻고, 그 뒤 슬롯은 답을 기다립니다.

중지

멈추면 화면의 답변은 바로 끝나 다음 질문을 할 수 있습니다. 서버에서는 실행 중인 스킬이 스스로 멈추고, 시작하지 않은 슬롯은 "중지했습니다"로 마감한 뒤 로그를 저장합니다. 연결이 끊겨도 같습니다. 중지·실패한 답변은 다시 열어도 그렇게 표시되고, 다음 질문의 대화 맥락에서는 빠집니다.

데이터 영역은 레이아웃이 나오고 곧바로 채워집니다. 일반적인 ETF·종목 질문은 7~10초, agent로 가는 질문은 15~45초가 걸립니다. 정기보고서 요약은 처음 읽는 보고서만 수십 초가 걸리고, 그 뒤로는 캐시에서 바로 나옵니다.

스킬

화면 한 영역을 채우는 단위. 이름 · 설명 · 인자 스키마 · 지원하는 표시 방식 · 실행 함수를 가지고, 레지스트리에 올리면 Planner의 선택지에 바로 들어갑니다.

스킬에 tool = True를 켜면 agent도 같은 인자로 부릅니다(슬롯과 같은 요약을 돌려받음). 기간 수익률·실적·차트 신호 같은 계산은 app/domain/에 두고 스킬과 스크리너가 함께 씁니다.

데이터 스킬의 숫자는 LLM을 거치지 않습니다. LLM에는 단위를 붙인 짧은 요약만 넘어가고, 화면의 표·차트는 DB 값으로 그립니다. 유일한 예외인 정기보고서의 매출 구성은 LLM이 표에서 옮긴 값을 원문과 대조해, 그대로 있는 것만 그립니다.

레이아웃은 이렇게 처리됩니다

LLM은 단순한 줄 목록을 내고, 서버가 이를 트리로 바꿔 보내면, 프런트가 트리를 격자로 그립니다.

1. Planner의 출력 — 줄 목록

rows:
  - slots: [etf_compare/table, etf_profile/radar]
  - slots: [price_trend/line]
  - slots: [narrative/text]

재귀 트리 대신 평평한 구조라 작은 모델도 안정적으로 채웁니다.

2. 서버가 보내는 레이아웃 트리

column
├ row
│ ├ slot s1  table  "기본 정보"
│ └ slot s2  chart  "프로필"
├ slot s3    chart  "가격 추이"
└ slot s4    text   "해설"

슬롯이 하나뿐인 줄은 row 없이 slot으로. 표시 방식은 스켈레톤 종류(chart · table · text · markdown)로 묶입니다.

3. 프런트의 화면

기본 정보table
프로필radar
가격 추이line
해설
  • column은 위에서 아래로 쌓고, row는 자식 수(1~3)만큼 열을 나눈 격자. 좁은 화면에서는 한 열로 접힙니다.
  • 내용이 오기 전에는 슬롯 종류에 맞는 스켈레톤(차트 상자, 표 줄, 텍스트 줄)을 보여 줍니다.
  • 데이터 영역은 테두리 있는 카드, 해설·마크다운은 테두리 없이 본문처럼.
  • slot complete를 받으면 GET /chat/logs/{id}/slots/{sid}로 내용을 가져옵니다. 해설은 slot_delta로 흘려받은 글을 그대로 씁니다.
  • 차트는 ECharts 빌더로 그리고, 언제든 표로 보기로 바꿀 수 있습니다. 모르는 차트이거나 그리지 못하면 같은 데이터를 표로.
  • 영역 아래에는 주석(어느 대상을 받아 그렸는지 등)과 출처·기준일.
  • 비었거나 실패한 영역은 그 자리에 이유만 표시하고, 나머지 영역은 그대로 둡니다.

4. 스킬이 영역을 나눌 때

계획
└ slot s5    markdown  "보고서 요약"

화면 (실행하며 나눈 뒤)
column
├ row
│ ├ slot s5-1  chart     "부문별 매출"
│ └ slot s5-2  chart     "제품별 매출"
└ slot s5-3    markdown  "2026년 반기보고서 요약"
  • 무엇을 보여 줄지 실행해 봐야 아는 스킬은 split 이벤트로 자기 영역을 나눕니다. 차트는 한 줄에 나란히, 텍스트는 그 아래.
  • 나눈 영역은 s5-1, s5-2… id로 따로 저장돼, 보통 슬롯처럼 slot 이벤트와 GET으로 채워집니다.
  • 계획(플래너가 보는 슬롯)은 그대로 s5 하나입니다. 원래 슬롯에는 나눈 영역들을 합친 결과가 남아 다시 설계·해설 대기 판단에 쓰이고, 해설은 나눈 영역의 요약을 하나씩 받습니다.
  • 제목만 바꿀 때는 title 이벤트. 두 경우 모두 서버가 layout을 다시 보내고, 마지막 레이아웃이 대화 기록에 남습니다.
다시 설계해도 배치(줄과 슬롯의 순서·개수)는 바꾸지 않습니다. 바뀐 슬롯만 비우고 새 레이아웃을 보내므로 이미 그려진 영역은 흔들리지 않습니다. 지난 대화를 열 때도 같은 GET으로 영역을 채워, 실시간 화면과 기록 화면이 같은 경로로 그려집니다.

해설
  • 차트는 가격(봉 + 이평) · 거래량 · 보조지표 세 칸. 오른쪽 위에서 표시 기간(1개월 · 6개월 · 1년, 질문한 기간이 다르면 그것도)을 고르고, 볼린저 밴드를 켜고 끄고(기본 꺼짐), ‹ ›로 보조지표를, "표로 보기"로 같은 데이터를 표로.
  • 표시 기간은 화면에서만 바뀐다. 일봉은 가장 긴 기간까지 한 번에 오고 프런트가 시작일부터 잘라 그린다. 조회 기간 주석·신호·해설은 질문한 기간 그대로.
  • 차트 아래에 신호 한 줄(추세 · MACD · RSI · 스토캐스틱). 강세는 빨강 ▲, 약세는 파랑 ▼ — 봉차트와 같은 국내 관례. "판정 기준"을 펼치면 위 규칙이 보인다.
  • 해설은 이동평균·MACD·RSI·스토캐스틱을 굵은 머리말 문단으로 하나씩. 값·정의·기준대로 지금 상태만 쓰고, 지지선·저항선·앞으로의 방향·매수·매도 판단은 쓰지 않는다.
  • 레이아웃 예시 두 개("주가 분석해줘", "RSI 어때?")가 기업 분석 예시와 갈라 준다.
신호는 정해진 규칙으로 본 강세·약세 상태이지 매수·매도 권유가 아닙니다. 대가들의 규칙도 검증된 법칙이 아니라 경험칙이라, 맞는지는 스크리너 백테스트로 따로 확인해야 합니다. 200일선 기울기와 52주 고저가 필요해 일봉이 약 260거래일보다 짧은 종목은 일부 신호가 "데이터 부족"으로 나옵니다.
