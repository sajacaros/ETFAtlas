오케스트레이터

특정 스킬을 모르는 실행기입니다. 스킬이 늘어도 바뀌지 않습니다.

질문 재작성
이전 대화가 있을 때만. "이거 구성종목은?" → "KODEX 반도체 구성종목은?"
~0.5초
레이아웃 설계 (Planner)
줄 목록, 줄마다 슬롯 1~3개. 슬롯마다 skill · display · args. 실패하면 agent 슬롯 하나로
2~6초
레이아웃 전송
슬롯에 s1, s2… id를 붙여 저장하고 SSE layout으로 보낸다. 프런트는 빈 자리를 그린다
즉시
슬롯 실행
끝나는 슬롯마다 chat_slots에 저장하고 SSE slot {id, complete}
1단계 · 독립 슬롯을 동시에 (슬롯마다 DB 세션)
2단계 · after_others 슬롯(해설)이 1단계 요약을 받아 실행
데이터 0.1초
해설 2~3초
답변 텍스트
화면 전체를 텍스트로 옮겨 SSE answer. 대화 기억과 관리자 검수에 쓴다
즉시
ETF·종목 질문은 7~10초, agent 슬롯으로 가는 질문은 15~45초. 데이터 영역은 레이아웃이 나오자마자 채워집니다.

이벤트 흐름

"KODEX 200과 TIGER 200 비교해줘" — POST /api/chat/message/stream

서버 → 프런트
session · status {planning}
서버 → 프런트
layout {chat_log_id, column[ row[s1 표, s2 레이더], s3 라인, s4 해설 ]} → 스켈레톤
서버 → 프런트
slot {s1, complete} · {s2, complete} · {s3, complete}
프런트 → 서버
GET /chat/logs/{id}/slots/s1 · s2 · s3 → 표 · 레이더 · 라인 차트
서버 → 프런트
slot_delta {s4, "두 ETF 모두…"} ×N → 해설이 글자 단위로
서버 → 프런트
slot {s4, complete} · answer · chat_log_id · [DONE]
지난 대화를 열 때도 같은 GET으로 영역을 채우므로, 실시간 화면과 기록 화면이 렌더링 경로를 공유합니다.
